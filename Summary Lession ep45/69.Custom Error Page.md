## Custom Error Pagfe (404 , 500)

### What are custom error page?

Custom error pages are user-friendly pages shown when something goes wrong, instead of ugly or technical error messages.

Example:

- 404 -> Page not Found
- 500 -> Server error (Bug, Crash, Exception)

### Why do we need custom error pages?

**Explain**

- ❌ Default error pages:
    - Scary
    - Techincal
    - Not User-Friendly

- ✅ Custom error pages:
    - Better UK
    - Professional Look
    - Don't expose sensitive information

### Real application NEVER show raw errors to users.

Where Laravel looks for errors pages

Laravel automatically checks this folder:

Location: `resources/views/errors`

- If the file exists -> Laravel uses it
- If not -> Laravel uses the default error page.

### Creating a Custom 404 Page

**Create this file:**
Location: `resources/views/errors/404.blade.php`

**_Example:_**

```php
//Blade
@extends('components.layouts.app')
@section('content')
    <div class="text-center">
        <h1>404</h1>
        <p>Sorry, the page you are looking for does not exist.</p>
        <a href="{{ url('/') }}">Go back to the homepage</a>
    </div>
@endsection
```

- ✅ Automatically used
- ✅ No routes needed
- ✅ No controller needed

### Creating a Custom 500 pagr

**_Create:_**

_Location 📁:_ `resources/view/errors/500.blade.php`

**_Example:_**

```php
//Blade
@extends('components.layouts.app')
@section('content')
    <div class="text-center">
        <h1>500</h1>
        <p>Something wrong please try again later!</p>
        <a href="{{ url('/') }}">Go back to the homepage</a>
    </div>
@endsection
```

**_Used When:_**

- An exception occurs
- App crashes
- production mode

### Important: `APP_DEBUG`

**APP_DEBUG=true**

- Shows detailed errors
- For development only

**APP_DEBUG=false**

- Hides errors
- Shows custom error pages
- Logs errors instead

📌 Custom error pages only matter when `APP_DEBUG=false`

### Common Error Pages You Can Create:

| Code | Meaning             |
| ---- | ------------------- |
| 404  | Page not found      |
| 403  | Unauthorized        |
| 419  | Page expired (CSRF) |
| 500  | Server Error        |

**Example:**

```
404.blade.php
419.blade.php
```

Laravel handles them automatically.

### Do we define routes for error pages?

- No
- Never

**Laravel:**

- Dectects the HTTP status code
- Loads the matching view automatically
- This is an important misconception to clear.

### Relation to Logging

Very Important concept:
- Users see -> custom error page
- Developers see -> logs in storage/logs


Both work together.
