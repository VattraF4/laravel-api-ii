## Laravel Jobs (Concetp Only)

### What is a Job?

> A Job is a class that represents a single task you want Laravel to execute.

### Think of a Jobs as:

---

> "This is a piece of work I want Laravel to do".

**Why Jobs Exist?**

Without jobs, everything happens inside the controller:

```php
// Controller
sendEmail();
resizeImage();
logActivity();
```

This makes controllers:

- Big
- Hard to read
- Hard to test
- Hard to reuse
- Jobs solve this by moving logic out of controllers.

### What a Job Does (Key Idea)

**A Job:**

Encapsulates on responsibility

**Can be:**

- Run immediately or later (with queues - later section)

**For now:**

👉 A Job is just clean, reusable logic.

### Creating a Job

```bash
php artisan make:job ProcessPost
```

_This Create:_

```php
class ProcessPost
{
    public function handle(): void
    {
        //logic here
    }
}
```

**Structure of a Job**

```php
class ProcessPost implements ShouldQueue
{
    use Queueable;

    public function __construct()
    {
        // recieve data here
    }

    public function handle(): void
    {
        // actual work
    }
}
```

### Key Part:

- \_construct() -> receives data
- handle() -> executes the task

**Simple Job Example (No Queue Yet)**

```php
//JOB
class LogPostCreation{
    public function _construct(public $post){

    }

    public function handle(){
        \Log::info('Post created: '. $this->post-id);
    }
}
```

**Controller**

```php
LogPostCreation::dispatch($post);
```

- Still runs syncronously
- But logic is cleanly separated



### Why This Matters (Teaching Point)

**Job help you:**

- Keep controllers thin
- Reuse logic
- Prepare for async processing later
- Write testable code

**Common Real-World Job Examples**

- Send welcome email
- Resize uploaded image
- Generate PDF
- Sync data with external API
- Log activity

**Event if they run now, they're written as jobs.


**Important Rule (Very Important)**

A Job should do one thing well

*Not for:*
- Save Post
- Send Email
- Notify users
- Log activity

❌ That's too much

#### The "One Thing Well" Rule (Single Responsibility)
>Not for: Save Post -> Send Email -> Notify Users -> Log Activity. ❌ That's too much.

This is the most important rule of queues, and here is the dangerous reason why: Retries and Partial Failures.

Imagine you put all four of those steps into a single job called PublishPostJob.

- The Job saves the post to the database. (Success!)

- The Job sends the email. (Success!)

- The Job tries to notify users via SMS, but the SMS API is down. (CRASH!)

Because the job crashed, Laravel's queue worker says, "Oh no, the job failed! Let me retry it from the beginning."
When it retries:

- It saves a duplicate post.

- It sends a second, duplicate email to the user (annoying them).

- It crashes at the SMS API again.

**The Fix:** You break them into separate jobs. `SavePostJob`, `SendEmailJob`, `NotifyUsersJob`. If the SMS fails, only the SMS job retries. The post is safely saved, and the email is only sent once.
