## Using Laravel Notifications (Emails)

### What is an Email Notifications?

An Email notification is a structured way to send emails to users using Laravel's notification system,

### Think of it as:

A smarter alternative to Mailables when the email i striggerd by an event related to a user.

**Example:**

- New Post published
- New comment
- Account activity alert
- Security notification

**Creating an Email Notification**

```bash
php artisan make:notification NewPostNotification
```

📁 File Create:
`app\Notifications\NewPostNotification.php`

#### Basic Notification Structure

```php

use Illuminate\Notifications\Messages\MailMessage;
use Illuminate\Notifications\Notification;

class NewPostNotification extends Notification
{
    /**
     * Get the notification's delivery channels.
     *
     * @return array<int, string>
     */
    public function via(object $notifiable): array
    {
        return ['mail'];
    }
}
```

- ✅ via() tells Laravel how to send the notification
- ✅ 'mail' means email only

Writing the Email Content

```php
public function toMail(object $notifiable): MailMessage{
    return (new MailMessage)
        ->subject('New Post Published')
        ->greeting('Hello'.$notifiable->name)
        ->line('A new Post has just been published.')
        ->action('View Post',url('/post'))
        ->line('Thanks for being with us!');
}
```

### _Important Point_

`$notifiable` is the user receiving the email.

**You can access:**

- $notifiable->name
- $notifiable->email

---

### Sending the Notification

**From a Controller**

```php
$user->notify(new NewPostNotification())
```

### Laravel Automatically:

- Finds the user's email
- Sends the notification
- Uses your email configuration

### Real-World Example (Explain)

> "When a new post is published, notify the author by email."

```php
post->user->notify(new NewPostNotitification());
```

- ✅ Clean
- ✅ Expressive
- ✅ Real-World Usage

### Why Email Notificaions Are Useful:

- Clean API
- No Blade required
- Easily extendable later (database, SMS)
- Built-in retry & queue support

#### 1. Why Notifications use `$notifiable`

#### 2. What is `$notifiable`?

In this Method:

```php
    public function toMail(object $notifiable): MailMessage

```

👉 `$notifiable` _Is The User Who Receives the Notification_

Laravel automatically passes it for you.

If you call:

```php
$user->notify(new NewPostNotification())
```

Then Inside function `toMail()`:

```php
$notifiable=== $user;
```

#### 3. Example: Understanding toMail():

```php
public function toMail(object $notifiable): MailMessage
{
    return (new MailMessage)
        ->subject('New Post Published')
        ->greeting('Hello ' . $notifiable->user)
        ->line('A new Post has just been published.')
        ->action('View Post', url('/post'))
        ->line('Thanks for being with us!');
}
```

**What's happening:**

```php
$notifiable->name; // user's name
```

Laravel already knows where to send the email.

#### 4. Why Laravel uses `$notifiable` instead of user?

\*\*Because notifications are generic.

Laravel doesn't care if the receiver is:

- User
- Admin
- Vendor
- Driver
- etc.

As long as the model:

```php
// In Model (User Model)
use Notifiable;
```

Laravel Treats is as "notifiable".

That's why the variable is named $notifiable, not $user.

**Summary**

> Laravel Notificaions (Email) are user-based emails triggered by application events.
