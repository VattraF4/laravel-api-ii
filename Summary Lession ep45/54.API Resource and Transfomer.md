### What problem do API Resource can solve?

**By Default, This:**

```php
return Post::with('user')->get();
```

❌ Returns:

- All columns
- Internal Fields
- Inconsistent structure
- Hard-to-change response format

💡 **API Resources transform your models into clean, controlled JSON responses.**

**What is an API Resource?**

> An API Resource is a presentation layer for your API.

- Decides what fields are returned.
- Controls nested relationships
- Keep `Controllers` clean
- Make APIs statble and professional

### Creating a Resource

```bash
php artisan make:resource PostResource
```

**📁 Location:**
`app\Http\Resources\PostResource.php`

**Basic PostResource**

```php
<?php

namespace App\Http\Resources;

use Illuminate\Http\Request;
use Illuminate\Http\Resources\Json\JsonResource;

class PostResource extends JsonResource
{
    /**
     * Transform the resource into an array.
     *
     * @return array<string, mixed>
     */
    public function toArray(Request $request): array
    {
        return [
            'id'=>$this->id,
            'title'=>$this->title,
            'subtitle'=>$this->subtitle,
            'body'=>$this->body,
            'user'=>$this->user,
        ];
    }
}
```

Returning a single resource

```php
return new PostResource($post)
```

**Result Reponse:**

```json
{
    "id": 1,
    "title": "My Post",
    "body": "Post body"
}
```

### When return multiple models we use:

#### Important

```php
return Resource::collection($agrument);
```

❌ If we use :

```php
return Post::all();
```

✅ We should use with previous above:

```php
return Post::collection(Post::all());
```

**Response:**

```json
[
    {
        "id": 1,
        "title": "The Post 1",
        "body": "Body one"
    },
    {
        "id": 2,
        "title": "The Post 2",
        "body": "Body two"
    }
]
```

## 📌**`collection()` applies the transformer to every item.**

## API Resource with nested relationships

### Load Relationship

- **Controller**

```php
$posts = Post::with('user')->get();

```

- **Resource API**

```php
return[
    'id' => $this->id,
    'title'=>$this->title,
    'user'=> [
        'id' => $this->user->id,
        'name' => $this->user->name,
    ]
]
```

⚠️ This assumes user is eager loaded.

\*\*Conditional Relationships (BEST PRACTICE)

```php
use App\Http\Resources\UserResource;

return [
    'id'=> $this->id,
    'title'=> $this->title,
    'user'=> new UserResource($this ->whenLoaded('user'))
]
```

- ✅ No errors
- ✅ No unnecessary data
- ✅ Clean Respone

### Where are Resource used?

📍 **Controllers ONLY**

```php
public function index(){
    return PostResource::collection(
        Post::with('user')->get();
    )
}
```

- ❌ Never inside models
- ❌ Never inside routes

### Real-World API rule

> Never return Eloquent model directly in proudction APIs.

**Always use:**

- API Resource
- Resource collection

### Resource vs Model (Very Important)

| Model                  | Resource                  |
| ---------------------- | ------------------------- |
| Handles database logic | Handles API out           |
| Knows everything       | Shows only what you allow |
| Unsafe to expose       | Safe for APIs             |
