## Conditional Rendering with Components (Blade)

What does "conditional redering" mean?

It means:

> Showing or hidding parts of a componenet based on a condition

Instead of writing `@if` everywhere in views, we move logic into components.

Why conditional rendering matters

Without Components:

```php
@if(auth()->check())
    <button class="btn btn-danger">Logout</button>
@endif
```

Problems:

- Repeated logic
- Messy views
- Hard to maintain

**With Components:**

- ✅More Clean
- ✅ Reusable
- ✅ Centralized ligc

### 1. Passing Conditions to Components

**Components**

```php
<!-- Blade's component/button.blade.php -->
@if ($show)

    <button class="btn btn-{{ $type ?? 'primary' }}">
        {{ $text ?? 'Button' }}
    </button>
@endif
```

**Usage:**

```php
<x-button type="danger" text="Delete" :show="auth()->check()" />

```

- ✅ Components decides when to render
- ✅ View stays clean

### 2. Using auth conditions inside components

You can use Laravel helpers directly inside components:

```php
@if(auth()->check())
    <div class="alert alert-success">
        Welcome Back!
    </div>
@endif
```

**Use Case:**

- Navbar links
- User Dropdown
- Logout Button

### 3. Conditional UI for roles or permissions

Example: Admin-only button

```php
@if(auth()->user()->role="admin")
    <button class="btn btn-warning"> Admin Panel </button>
@endif
```

### 4. Rendering different content with slots

In route or controller logic: you need to pass `$saved = true` or `false`

Conponent code:

```php
<!-- Blade Code -->
@props(['success', 'error'])

@if($success)
    <div class = "alert alert-success">
        {{$slot}}
    </div>

@else
    <div class= "alert alert-danger">
        {{$error}}
    </div>
@endif
```

**Triggering Componenet**

```php
// Blade Trigger (Usage)

<x-alert :success="$save" error= "Something went wrong">
    Saved successfully!
</x-alert>
```
