### Request Validation & From Requests (Laravel APIs)

---

### 1. Why Validation is Critical in APIs

### Exaplain :

- APIs don't have form you to control
- Anyone can send bad data
- Frontend, mobile, or even hackers can hit your endpoint

> "Never trust API input -even if it comes from your own frontend."

### 2. Inline Validation (Quic Intro)

Laravel allows validation directly in controllers:

```php
$request->validate([
            'title' => 'sometimes|required|string|max:255',
            'subtitle' => 'sometimes|nullable|string|max:255',
            'body' => 'sometimes|required|string',
            // 'image' => 'sometimes|nullable|image|mimes:jpeg,png,jpg,gif,svg|max:2048',
            'image' => 'sometimes|nullable|string|max:255',
            'user_id' => 'sometimes|required|exists:users,id',
            'status' => 'sometimes|required|in:draft,published,archived',
        ]);
```

### If validation fails in API:

- Laravel automatic returns response code 422
- Response is JSON
- No redirect

---

### Explain

> "Same method as web validation, different behavior."

### 3. Why Inline Validation is not Enough

- ❌ Controllers become large
- ❌ Validation logic is repeated
- ❌ Hard to miantain

> " Controllers should coordination logic - no validate everything."

### 4. Form Requests (The Correct Way)

Form Requests are didicated validation classes.

```bash
php artisan make:request StorePostRequest
```

=> `app\Http\Requests\StorePostRequest.php`

### 5. Form Request Structure

```php

class StorePostRequest extends FormRequest
{

    public function authorize(): bool
    {
        return true; // <- turn this to true , default with false
    }
    public function rules(): array
    {
        return [
            'title' => 'required|string|max:255',
            'subtitle' => 'nullable|string|max:255',
            'body' => 'required|string',
            // 'image' => 'nullable|image|mimes:jpeg,png,jpg,gif,svg|max:2048',
            'image' => 'nullable|string|max:255',
            'user_id' => 'required|exists:users,id',
            'status' => 'required|in:draft,published,archived',
        ];
    }
}
```

### Explain:

- authorize() -> permission check (later wiwth policies)
- rules() -> validation rules.

---

### 6. Using Form Requests in API <span style ="color:red"> Controllers </span>

Replace Request with your Form Request:

```php
use App\Http\Requests\StorePostRequest;

class PostController extends Controller{
    public function store(StorePostRequest $request)
    {
        //48. Validate the request data from the StorePostRequest class

        $post = Post::create($request->all());

        return response()->json([
            'success' => true,
            'message' => 'Post created successfully',
            'data' => $post
        ], 201);
    }
}
```

📌 Teaching Line:

> " If the method runs, validation already passed."

### 7. API Validation Error Response (Automatic)

When validation fails, Laravel returns:

```json
{
    "message": "The given data was invalid.",
    "errors": {
        "title": ["The title field is requred."]
    }
}
```

### Status:

> 422 Unprocessable Entity

No Extra code needed.

### 8. Customizing API Validation messages (Optional)

```php
public function messages(): array
{
    return [
        'title.required' => 'Post title is required'
    ];
}
```

### 9. Validating Update Requests

**Create a separate request:**

```bash
php artisan make:request UpdatePostRequest
```

Why:

- Create rules ≠ Updates Rule
- Some fields optional in update

### 10. Common Beginner Mistakes

- ❌ Validating in models
- ❌ Mixing validation and business logic
- ❌ Returning 200 on validation errors
- ❌ Skipping validation for "trusted" clients

### 11 Teaching Summary

Say this clearly:

> " Validation protected your APIs, your database, and your reputation."
