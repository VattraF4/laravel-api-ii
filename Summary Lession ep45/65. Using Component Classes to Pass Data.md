## Why do Blade Components have PHP Classes?

**_The Core Idea:_**

> Blade component classes exist to separate logic from HTML.

Blade = UI

Component class - logic for that UI

### First: What is a Blade Component?

A Blade component is a reuable UI piece:

- Buttons
- Alerts
- Cards
- Layouts

Instead of repeating HTML, we reuse it.

## Ther are TWO types of Blade components

### 1. View-Only components

```bash
# if we use --view flage
php artisan make:component Alert --view
```

Only a blade file:

`resources\views\components\alert.blade.php`

**Used When:**

- No Logic
- No defaults
- Just markup

Example:

```php
<div class="alert alert-success">
    {{$slot}}
</div>

```

- ✅ Simple
- ❌ Not Flexible

## Class-Based Components

Blade file + PHP class:

```bash
# if we command withou --view flage

php artisan make:component Alert
```

It will create:

- `resources\views\components\alert.blade.php`
- `app\View\Components\Alert.php`

Now Laravel gives you a class to prepare data.

Why does Laravel give us a class?

=> Because Blade should not think.

**Blade Should:**

- dispaly data
- render HTML

**Blade Should NOT:**

- Calculate
- Decide defaults
- Contain logic

That logic belongs in PHP.

What the component class accully does?

The Component class:

- Receives props
- Sets default values
- Prepares data
- Keeps blade clean

**Example:**

```php
class Alert extends Component
{
    public $type;
    public function __construct($type = 'success')
    {
        $this->type = $type;
    }
}

```

**_Blade:_**

```php
@props(['success', 'error'])

@if ($success)
    <div class="alert alert-{{$type}}">
        {{ $slot }}
    </div>
@else
    <div class="alert alert-{{$type}}">
        {{ $error }}
    </div>
@endif
```

**_Usage:_**

```php
    <x-alert :success="$save"  error="Error Happened!">
        Create Post Successfully!
    </x-alert>
```

Why not put logic in Blade?

**Bad:**

```php
@if($type === 'danger')
```

**Good:**

```php
$this->type = $type?? 'success';
```

Blade is for rendering, not reasoning

**When do you NEED a component class?**

Use class when:

- You need defaults
- You need computed values
- The component is reused a lot
- You want clean Blade files.

**Do NOT use a class when:**

- Static HTML
- No logic
- One-time usage

### Real-World analogy (Great for video)

Controller -> prepares data for a page.
Component class -> prepares data for a UI piece.

Same concept, smaller scope.

### One-Line takeaway (end the video with this)

> Blade components have classes so views stay clean and logic stays in PHP

### Who does what? (very important)

| Task      | Component Class | Blade |
| --------- | --------------- | ----- |
| Logic     | ✅              | ❌    |
| Defaults  | ✅              | ❌    |
| Data prep | ✅              | ❌    |
| HTML      | ❌              | ✅    |
| Slots     | ❌              | ✅    |
